# Puzlea v1 Implementation Plan

> **For agentic workers:** Implement the tasks in order in this repository. The user selected native execution in this session. Keep changes in focused commits. Do not add or run tests.

**Goal:** Ship the local-first Puzlea puzzle app with exact save/import/print behavior and optional moderated sharing.

**Architecture:** React/Vite presents the game; a serializable puzzle model owns grid geometry and play state. Browser adapters provide IndexedDB, JSZip and pdf-lib, while a separately configured Supabase client handles accounts and approved public submissions behind RLS.

**Tech Stack:** React, Vite, SVG, IndexedDB, JSZip, pdf-lib, Supabase JS.

**Spec:** `docs/superpowers/specs/2026-10-07-puzlea-design.md`

## Global Constraints

- Supported puzzle sizes are exactly 24, 48, 96 and 192 pieces.
- SVG game paths and PDF cut paths must come from the same stored geometry.
- Local puzzle state and images remain on the device unless a signed-in user explicitly submits a copy.
- Sharing uploads are private and pending until manual approval; public reads expose only approved puzzles.
- Never expose Supabase service-role secrets in client code or environment variables prefixed for Vite.
- Do not deploy the website or add/run automated tests.

## Review Focus

- Image imports can exceed available memory or use unsupported MIME types; enforce a size/type limit and show a clear error.
- ZIP imports can be malformed or have an unsupported version; validate before replacing active state.
- A failed IndexedDB write must not imply that a save succeeded; surface a message while keeping play available.
- Pending Storage paths must not be visible to anonymous users; enforce both row and object policies.
- Multi-page print seams must align; include overlap and repeated registration marks.
